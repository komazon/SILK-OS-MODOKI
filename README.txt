SILK OS 命令仕様書
書き方:
NAME 引数1 引数2 引数3 引数4

コマンド
PRINT
RAMの引数1番を1行書き出す(/nで改行できないぜ)

CLEAR
画面をクリアする

RAMIK
RAMの引数1番目アドレスにある数値のアドレスのRAMを引数2の内容で置き換える
RAMI系は書き方が異なるので例文:RAMIK 1"hello world"

RAMOK
RAMの引数1番目アドレスにある数値のアドレスの内容を返り2にかきだす
RAMの引数2番目アドレスにある数値のアドレスの内容を返り3にかきだす
RAMの引数3番目アドレスにある数値のアドレスの内容を返り4にかきだす

RAMI
RAMの引数1番目アドレスを引数2の内容で置き換える
RAMI系は書き方が異なるので例文:RAMI 1"hello world"

RAMO
RAMの引数1番目アドレスを返り2にかきだす
RAMの引数2番目アドレスを返り3にかきだす
RAMの引数3番目アドレスを返り4にかきだす

OURAI
RAMの引数1番目アドレスに返り値リスト引数2番目のRAMアドレスの内容を書き出す

INPUT
SILK OSの入力システムを呼び出し(終了キー:RAMの引数2アドレスの内容。たとえばENTERならenterと書く。行:RAMの引数3アドレスの数値であり、画面描画の時にどのラインにINPUTをするかで、1始まり)、
内容をRAMの引数1番目に書き出す

JMP
PCを引数1のRAMアドレスの内容のラベルの場所にする

IF
引数1が引数2の時は返り2をTRUE、そうでないときFALSEにする

MKDIR
引数1の階層に引数2の名前のディレクトリを作る

LS
引数1のRAMアドレスの内容のディレクトリのファイルをリストアップし、返り値2にディレクトリのファイル数、返り値3にファイル名を『/n』で区切って書き込む

MKF
引数1の階層に引数2の名前のファイルを作る

CD
引数1にCDする。ユーザーがコマンドラインに戻るとディレクトリが変わってる。なんでだろうねぇ？w

LFILE
ファイルの行数を返り2に出力、引数1のパスにあるファイルをディスクの実際の形式(data/ndata/n)
で返り3に出力

RM
引数1のディレクトリまたはファイルを削除

WFILE
引数1のファイルにディスクの実際の形式(data/ndata/n)でRAMの引数2番目を書き込める

PLUS
引数1の内容と引数2の内容を足して返り値2に書き出す

MYEPT
(正式名称はMyEggPlant。MYEPTと書かないと使えません)
引数1の内容と引数2の内容を引いて返り値2に書き出す

MTP
引数1の内容と引数2の内容をかけて返り値2に書き出す

DIV
引数1の内容と引数2の内容を割って返り値2に書き出す

LAB
ラベルである。
LAB 名前
※LAB単体は何もしない実装です。名前は即値

DEKAI
引数1<引数2の時に『TRUE』、それ以外の時は『FALSE』を返り2に書き出す

ERROR
強制的にエラーを発生させる(返り1が1になるだけ)

EXIT
プログラムはおわりじゃい！

WAIT
引数1のRAM場所の内容秒まつ(ドットで小数点OK)

MOD
引数1/引数2のあまりを返り2に

SUBSTR
引数1の引数2番目の文字を返り2に出力(ない場合は無が出力されます。1起点)

CAT
引数1と引数2の文字列を接続して返り2に出力

LEN
引数1の長さを返り2に書き出す

APPEND
引数1で指定されたファイルに実際の形式(data/ndata/n)でRAMの引数2番目を書き足し

PWD
Currentを返り2に出力

H
時を返り2に出力

M
分を返り2に出力

S
秒を返り2に出力

MO
月を返り2に出力

D
日を返り2に出力

Y
年を返り2に出力

JT
引数1=引数2の時に引数3のRAMアドレスの内容のラベルの場所にJMP

JF
引数1=引数2ではない時に引数3のRAMアドレスの内容のラベルの場所にJMP


RAND
引数1以上引数2以下の乱数を返り2に出力

PROG
RAMの引数1アドレスの内容のディレクトリのプログラムを起動(現在のプログラムは終わり、すべてリセットされます)

NSPLIT
『/n』で仕切ります。
RAMの引数2番目の文字列からRAMの引数1番目の値-1番目の/nからRAMの引数1番目の値番目の/nまでの値を/nを抜いて返り2に書きだす

HIKI
引数1のRAMアドレスの内容の番目の引数を返り2に書きだす
引数2のRAMアドレスの内容の番目の引数を返り3に書きだす
引数3のRAMアドレスの内容の番目の引数を返り4に書きだす


返り値の仕様

リストで次のようになっています

実行成功/失敗(0or1ですが実質意味はないです。ただの飾りです。真偽値ではありません)
返り2
返り3
返り4


改行文字
『/n』です

演算は当たり前ですがScratchと全く同じ仕様です
ディレクトリなどはSILK OSの仕様に従っています

基本的にRAMIとRAMO以外では引数で即値ではなくRAMアドレスを指定します
指定場所のRAM上データ(文字列または数値)が読み込まれます

RAMアドレスはSILK OS26.4で1~1024までです

RAMI系では/nを書いても改行されませんが、そのデータをファイルに書き込むと改行されます

ゼロ除算は0が出力されます

返り値は毎回処理終了時に前回の返り値がリセット→書き込みされます

存在しないラベルの場合はPCが0になって最初からになります

x mod 0 =NaNです

RAMは最初、無が入っており空です

範囲外のRAMアドレス(0や1025以上)、数値でない値を RAMIK/RAMOK のアドレスに使うと何も起こりません
